    Part 6: Choosing a model

    Author

    Katy Brown

    NoteSections
    TipLearning objectives

    By the end of this part of the practical you will be able to:

    When we fit a model, we generally aim for the simplest model that adequately fits the data. We can therefore simplify a model by removing explanatory variables, provided that doing so does not significantly worsen the fit of the model. The simplest model which adequately fits the data is known as the minimal model.

    The approaches we use for model comparison apply to both linear models and to both binomial and Poisson GLMs, although the specific statistical test used to compare nested models differs between linear models and GLMs.

    For linear models, the residual sum of squares (RSS) measures the discrepancy between the observed values and those predicted by the model. For GLMs, the equivalent role is played by deviance (see Assumptions of Poisson GLMs) - a measure of how much mismatch remains between the observed data and the fitted GLM - or, in other words, of how well the model fits the data.In both cases, simplifying a model will generally worsen its fit, and we can test whether this worsening is sufficiently large to justify retaining the more complex model.

    We will use our **Septin* dataset to determine if the \(P_n\) of the six Septin proteins can be used to predict if an HSC is young or old, and to explore the methods of establishing a minimal model.

    Nested models and backwards stepwise elimination

    One model is nested within another if the simpler model can be obtained just by removing one or more terms from the more complex model.

    For example, in the following example model 1 is nested within model 2.

    model_1 <- lm(y ~ temperature, data = ...)
model_2 <- lm(y ~ temperature + rainfall, data = ...)

    Similarly, in the following case, model 1 is nested within model 2, because model 2 expanded to y ~ temperature + rainfall + temperature:rainfall, where temperature:rainfall is the interaction.

    model_1 <- lm(y ~ temperature + rainfall, data = ...)
model_2 <- lm(y ~ temperature * rainfall, data = ...)

    We can manually remove elements from a nested model and see how the model is affected.

    There are various options to choose which element to remove, including:

    • Sequentially removing the element with the highest p-value - the element with the least significant effect on the model fit.
    • Removing the element whose removal results in the lowest AIC - a statistic which specifically balances how well the model fits with the complexity of the model.

    Likelihood-Ratio tests

    As we removed explanatory variables from our model, the residual deviance increased. However, this does not tell us whether the increase in deviance is large enough to indicate that removing a variable has significantly worsened the fit of the model.

    For nested GLMs, we can test this using a likelihood-ratio test (LRT). The null hypothesis is that the simpler model fits the data adequately compared with the more complex model. A significant result therefore indicates that removing the variable has significantly worsened the fit of the model. The test is based on the ratio of the likelihood of our observed data given the two different models.

    For our nested GLMs, the difference in residual deviance between two adjacent points is identical to the likelihood-ratio test statistic.

    The test statistic for a likelihood ratio test is:

    \[ LR = 2\left[\log(L_{\text{full}}) - \log(L_{\text{reduced}})\right] \] We can measure the log-likelihood of a model using the R function logLik().

    The test statistics for likelihood-ratio tests are approximately chi-squared distributed, with degrees of freedom as the difference between the residual degrees of freedom for the two models.

    \[ df_{\mathrm{LR}} = df_{\mathrm{reduced}} - df_{\mathrm{full}} \]

    For a linear model, the process above is very similar. As for the GLM, we sequentially remove the predictor with the highest p-value from the model.

    Instead of deviance, we use the sum of the residual sum of squares (RSS) for each model, sum(residuals(model)^2). Conveniently but confusingly, you can also use the deviance(model) function in R to get this value from a fitted linear model.

    Instead of a likelihood ratio test, we calculate the test statistic F as follows:

    \[ F = \frac{ (RSS_{\mathrm{reduced}} - RSS_{\mathrm{full}}) / (df_{\mathrm{reduced}} - df_{\mathrm{full}}) }{ RSS_{\mathrm{full}} / df_{\mathrm{full}} } \] This statistic follows approximately an F-distribution, so we find the p-value using the function pf(). The degrees of freedom for the F-distribution are as follows:

    \[ df_1 = df_{\mathrm{reduced}} - df_{\mathrm{full}} \]

    \[ df_2 = df_{\mathrm{full}} \]

    Removing elements by AIC

    Now let’s try finding a minimal model using the AIC (Akaike Information Criterion) rather than p-value to choose which explanatory variables to remove.

    The AIC for a model is calculated based on its log likelihood and \(k\), the number of parameters in the model. It is implemented in the R function AIC().

    \[ AIC = -2\log(L) + 2k \] We can calculate the AIC of a model directly:

    aic_septin_m1 <- AIC(model_1)
print (aic_septin_m1)
    [1] 960.9955

    This just tells us the AIC of the model, not the contribution of each variable. If we want to know how the AIC would change if we removed each variable in turn, we can use the function drop1().

    aic_drop1 <- drop1(model_1)
print (aic_drop1)

    Note 41.1

    Automating backwards stepwise selection

    The process we have just carried out — starting with a full model and sequentially removing variables — is known as backwards stepwise selection.

    R can automate this process using the step() function with the argument direction = "backward". By default, step() uses AIC to decide whether removing a variable improves the model.
