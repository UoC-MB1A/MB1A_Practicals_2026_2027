    As you may have noticed, all of the statistical tests introduced in Practical 4 (except for chi-squared) expect a continuous response variable.

    A standard linear model assumes that the response variable is continuous, with observations normally distributed around an expected value. A linear combination of the explanatory variables determines this expected value.

    However, not all response variables are continuous or normally distributed. A generalised linear model (GLM) extends the idea of a linear model to response variables with other distributions.

    Binomial response variables

    In Part 2: Hypothesis Testing, we treated the presence or absence of a species as our explanatory variable when asking whether mean temperature differed between sites where a species was present and absent. We then used our model to predict mean temperature in the presence of this species in Part 6: Using models to make predictions.

    However, we may instead want to ask: does the probability of species presence change with temperature?

    In the case of H. tumulorum we would therefore have the following hypotheses:

    • Alternative: There is a relationship between minimum temperature in the coldest month and the probability of detecting H. tumulorum.
    • Null: There is no relationship between minimum temperature in the coldest month and the probability of detecting H. tumulorum.

    In this case, detection of H. tumulorum becomes our response variable and minimum temperature becomes our explanatory variable.

    Our response variable is binary: at each site H. tumulorum was either detected (1) or not detected (0). We can model this using a binomial distribution, where \(p\) represents the probability of detection. We therefore need our predicted values of \(p\) to lie between 0 and 1.

    Why not use a linear model?

    Let’s try just using a linear model. First, we need to load our H. tumulorum dataset. We should also use the as.integer() function to convert our logical (TRUE / FALSE) detected column into a numerical column with 1 for detected and 0 for not detected.

    A linear model can predict any numerical value, whereas a probability must always lie between 0 and 1 (0–100%). We therefore need a model that retains the useful linear relationship with our explanatory variable, but converts its predictions onto a scale appropriate for a probability.

    Link functions in binomial GLMs

    Link functions connect the predictors in our model to the response variables in a linear way.

    In a binomial GLM, the logit link function transforms probabilities into log-odds.

    \[ \operatorname{logit}(p) = \ln\left(\frac{p}{1-p}\right) \]

    ExerciseExercise 2

    In your prac6_exercises.qmd Quarto file, write a function to calculate the log-odds from a probability. In R log() is the natural logarithm.

    Use your function to calculate the log-odds for a sequence of probabiliies from 0 to 1, with increment 0.1. Observe what happens to the log-odds as the probability increases.

    # Write the function
calc_log_odds <- function(prob) {
  odds <- prob / (1 - prob)
  log_odds <- log(odds)
  return(log_odds)
}

# Apply the function to the sequence
lo_vec <- c()
for (val in seq(0, 1, 0.1)) {
  lo <- calc_log_odds(val)
  lo_vec <- c(lo_vec, lo)
}
print(lo_vec)
     [1]       -Inf -2.1972246 -1.3862944 -0.8472979 -0.4054651  0.0000000
 [7]  0.4054651  0.8472979  1.3862944  2.1972246        Inf

    There is an increase in log-odds as probability increases.

    The natural logarithm of the odds (log-odds) can take any value from \(-\infty\) to \(\infty\). We can therefore model the log-odds as a linear combination of our explanatory variables.

    Fitting binomial GLMs in R

    If we use a GLM instead of a linear model, it estimates the linear relationship between minimum temperature and presence / absence on the log-odds scale.

    We can apply a GLM in R glm() function. We use the argument family = binomial to specify that we want to predict a binomial response. Otherwise, the function is applied in the same way as a linear model, but with glm() instead of lm().

    Estimating model parameters using maximum likelihood

    R uses maximum likelihood to estimate the parameters for the model.

    Let’s fit a two-parameter model to some simple data. Seagulls like to steal chips, and are more common near to the sea.

    You’ve been provided with a dataset in data/seagulls.csv.

    Draw a brief conclusion

    The estimated coefficient for distance from the sea is -0.522. As distance from the sea increases, the log-odds of having your chips stolen by a seagull therefore decreases (\(p\) = 0.0012). We therefore reject the null hypothesis and conclude that there is evidence of an association between distance from the sea and the probability of having your chips stolen by a seagull.

    In this case, R will have estimated both \(\beta_0\) (1.3711) and \(\beta_1\) (-0.5219) using maximum likelihood estimation. This process finds the values of the model parameters that make the observed data most likely.

    To understand how this works, let’s fix \(\beta_0\) at 1.3711 and calculate the likelihood of the observed data for a range of possible values of \(\beta_1\), from -1 to +1.

    The model we are using is therefore:

    \[ \operatorname{logit}(p_{\text{stolen}}) = 1.3711 + \beta_1 \times \text{distance from sea} \]

    We can then try a range of values of \(\beta_1\) and see which value gives us a model with the highest likelihood of our observed data.

    For each observation in the data frame, we calculate the probability of the outcome that was actually observed, given its distance from the sea and the value of \(\beta_1\) being tested. We then combine these probabilities to calculate the likelihood of the complete dataset.

    For convenience, we use the logarithms of the probabilities. This allows us to add log-probabilities rather than multiplying together many very small probabilities. The value of \(\beta_1\) that gives the highest log-likelihood will also give the highest likelihood.

    For each value of \(\beta_1\) we will:

    • Use the model equation and each observed distance_from_sea value to calculate the log-odds of chips being stolen.
    • Convert the log-odds to a probability using the inverse logit equation:

    \[ p = \frac{e^{\text{log-odds}}}{1 + e^{\text{log-odds}}} \]

    • For rows where chips_stolen is TRUE, add the log of the probability of the chips being stolen, \(\log(p)\), to the total log-likelihood.
    • For rows where chips_stolen is FALSE, add the log of the probability of the chips not being stolen, \(\log(1-p)\), to the total log-likelihood.
    • Select the value of \(\beta_1\) that gives the highest log-likelihood.
    possible_beta1s <- seq(-1, 1, by = 0.01)
log_likelihoods <- c()
b0 <- coef(seagull_glm)["(Intercept)"]

for (beta in possible_beta1s) {
  # Calculate log-odds using this possible coefficient
  log_odds <- b0 + beta * pull(seagulls, distance_from_sea)
  
  # Convert log-odds to probability
  probs <- exp(log_odds) / (1 + exp(log_odds))
  
  # Filter the data frame to only rows where chips
  # were stolen and add a row with the probability
  # of this happening under the model
  chips_stolen <- seagulls |>
    mutate(probs = probs,
           log_probs = log(probs)) |>
    filter(chips_stolen == TRUE)

  # Filter the data frame to only rows where chips
  # were not stolen and add a row with the probability
  # of this happening under the model
  chips_not_stolen <- seagulls |>
    mutate(probs = (1 - probs),
           log_probs = log(probs)) |>
    filter(chips_stolen == FALSE)

  # Calculate the log likelihood of the observed data
  tot_stolen <- chips_stolen |> pull(log_probs) |> sum()
  tot_not <- chips_not_stolen |> pull(log_probs) |> sum()
  log_likelihood <- tot_stolen + tot_not
  
  # Add this to our vector of log likelihoods
  log_likelihoods <- c(log_likelihoods, log_likelihood)
}

# Put the results into a data frame
df_likelihood <- tibble(beta = possible_beta1s,

    Note that maximising the likelihood and maximising the log-likelihood will identify the same value of \(\beta_1\). Log-likelihood is generally more convenient to work with because it allows products of many small probabilities to be replaced by sums of their logarithms, avoiding extremely small numbers.

    Parameter space

    We are looking for the most likely value of a single parameter, so we can test a suitable range of possible values. However, we have used R’s estimate for \(\beta_0\). Without this, we would need to find the combination of \(\beta_0\) and \(\beta_1\) that gives the highest likelihood of observing our data, requiring us to search across a two-dimensional parameter space.

    With additional parameters, the number of dimensions increases and the search becomes increasingly complex.

    In practice, glm() uses an optimisation algorithm to find the combination of parameter values that maximises the likelihood, rather than testing every possible combination.

    Assumptions

    Some assumptions are common to all GLMs and some are specific depending on the type of response variable.

    For all GLMs we assume:

    • Independence of observations - this is mostly a study-design/data-structure issue.

    • Linearity on the link scale - GLMs assume that the linear predictor is linear with respect to the explanatory variables

    For binomial GLMs we additionally assume that the response is compatible with a binomial distribution (see The binomial distribution).
