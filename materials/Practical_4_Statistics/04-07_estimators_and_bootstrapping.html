    Estimators

    Extension

    An estimator is a statistic calculated from a sample that we use to estimate an unknown characteristic of the wider population. Different estimators can be used to estimate the same population parameter, and they may differ in how accurately and consistently they do so.

    For example, let’s concentrate on a single aspect of the data for now - the species richness, measured as the number of unique species.

    Across the whole dataset, we can find the number of unique species using our insect_counts data frame.

    n_unique_species <- insect_counts |>
  distinct(species) |>
  nrow()
print(n_unique_species)
    [1] 239

    There are 239 unique species.

    The data we have here are themselves only a sample of the real population. For this exercise, however, we will pretend that the complete dataset is our population. This allows us to repeatedly sample from a known pseudo-population and observe how our estimators behave across different samples.

    Let’s say we wanted to estimate the total species richness across the full data set based on 20 sites and we have three possible estimators:

    • Observed richness - total number of unique species across 20 sites
    • Scaled observed richness - total number of unique species across 20 sites * (total number of sites / 20)
    • The Chao1 richness estimator, which uses the number of rare species in the sample to estimate how many species may have gone undetected.

    First let’s take a sample of 20 random sites.

    random_sites <- site_metadata |>
  distinct(x1km_square) |>
  slice_sample(n = 20) |>
  pull(x1km_square)

    Now we can extract these rows from our insect counts data frame. For this part of the practical, we’re not interested in insects with a count of 0.

    insect_sample <- insect_counts |>
  filter(
    x1km_square %in% random_sites,
    n_observed != 0
  )

    Observed richness

    The observed richness is just the total number of unique species observed across all sites.

    obs_rich <- insect_sample |>
  distinct(species) |>
  pull(species)
n_obs_rich <- length(obs_rich)
print(n_obs_rich)
    [1] 169

    The observed richness estimator for this sample is 169.

    Scaled observed richness

    The scaled observed richness is the total number of unique species observed across all sites, multiplied by (total number of sites / number of sites in sample).

    n_sites_sample <- 20
site_count <- nrow(site_metadata)
scaled_obs_rich <- n_obs_rich * (site_count / n_sites_sample)
print(scaled_obs_rich)
    [1] 642.2

    The scaled observed richness estimator for this sample is 642.

    Chao1 estimator

    The Chao1 estimator estimates unseen species based on the number of species represented only once or twice in your sample.

    \[ \hat{S}_{Chao1} = S_{obs} + \frac{f_1^2}{2f_2} \]

    where:

    • \(S_{obs}\) is the number of species observed in the sample.
    • \(f_1\) is the number of species observed exactly once (singletons).
    • \(f_2\) is the number of species observed exactly twice (doubletons).
    Note

    You do not need to remember this - it is just an example of an estimator.

    obs_per_insect <- insect_sample |>
  group_by(species) |>
  summarise(n_total = sum(n_observed))

once <- obs_per_insect |> filter(n_total == 1)
twice <- obs_per_insect |> filter(n_total == 2)

n_once <- nrow(once)
n_twice <- nrow(twice)

chao <- n_obs_rich + ((n_once^2) / (2 * n_twice))
print(chao)
    [1] 197.1739

    The chao1 estimator for this sample is 197.

    None of these did a particularly good job of finding our real value of 239.

    However, you can’t measure how good an estimator is based on a single sample. Let’s try simulation and generate multiple samples.

    Remember (from the lectures): An unbiased estimator gives the correct value on average across repeated samples. The efficiency of an estimator is determined by its variance: estimators with lower variance give more consistent estimates. Mean squared error (MSE) combines bias and variance and measures how far, overall, estimates tend to be from the true value.

    Bootstrapping

    In the example above, we treated our full dataset as a pseudo-population from which our sample was taken. However, in most experiments we will only have our sample and not have the opportunity to re-sample from the population.

    In these cases, we can use an approach called bootstrapping to estimate the uncertainty in our estimate. We repeatedly re-sample, with replacement, from our observed dataset and re-calculate the estimator for each sample. The resulting bootstrap distribution approximates the sampling distribution of our estimator and allows us to quantify its uncertainty.

    Because we do not know the distribution of values in the whole population, we use our observed sample as an approximation. Each bootstrap sample therefore contains the same number of observations as the original sample, but observations are sampled with replacement. This means that some observations may appear several times in a bootstrap sample, while others may not appear at all. Repeating this process many times shows us how much the value of our estimator changes between bootstrap samples, giving us an estimate of its uncertainty.

    We keep the bootstrap sample size the same as the original sample so that the bootstrap replicates mimic repeatedly collecting samples of the same size as the one we actually observed.

    One simple way to construct a bootstrap confidence interval is the percentile method: we take the middle 95% of values in the bootstrap distribution, using its 2.5th and 97.5th percentiles.

    Invertebrate dataset

    For this exercise, we will use a different dataset. In this publication, published in Nature in 2026, the authors investigated the potential of marine invertebrates as a food source, and found these organisms to be very nutrient dense, with the potential to feed billions of people.

    They sourced data on nutrient content and various ecological characteristics from numerous organisms, however most of the records are incomplete. In data/marine_invertebrates.csv you have been provided with data from the 85 organisms for which data is available for the following measurements:

    • lmax - maximum length
    • depth_range_deep - maximum depth
    • FE - iron mg / 100g
    • CA - calcium mg / 100g
    • MG - magnesium mg / 100g
    • order - taxonomic order

    We have 85 observations in total, let’s say we want to know how accurately we can measure the median iron concentration for the population based on these observations.

    Bootstrap confidence intervals

    Bonus

    The technical definition of a confidence interval in this context is: if we repeatedly collected samples and constructed 95% confidence intervals using this method, approximately 95% of those intervals would contain the true population value.

    To illustrate, let’s generate simulated data which represents the time interval between someone deciding to do an unappealing task and them actually starting to do it. It is gamma distributed with a shape parameter of 2 and a scale parameter of 10 and therefore a population mean of 20 minutes. We want to find the bootstrap distribution of a specific metric, the 75th percentile - the time by which 75% of people will have started the task, or equivalently, the minimum procrastination time for the slowest 25% of the population.

    The true population value for the 75th percentile is 26.93, calculated as qgamma(0.75, shape = 2, scale = 10).

    ExerciseExercise 4 - Bootstrapp confidence intervals

    Bonus

    In your prac4_exercises.qmd Quarto file:

    • Take a sample of 200 individuals from the above population 100 times, then, within that sample, use bootstrapping with 100 replicates to calculate a 95% confidence interval for the 75th percentile of the data. Record whether or not the confidence interval contains the true population value of 26.9263453.

    • Across the 100 samples, calculate the proportion of bootstrap confidence intervals which contain the true population value.

    AnswerAnswer 
    # Calculate the population 0.75 quantile
pop <- qgamma(0.75, shape = 2, scale = 10)

# Make a vector to store the results
results <- c()
# Repeat 100 times
for (i in seq_len(100)){
  # Sample 200 individuals
  samp <- rgamma(200, shape = 2, scale = 10)
  # Put the results into a data frame
  samp_df <- tibble(time = samp)
  # Make a vector to store the quantiles
  quans <- c()
  # Repeat 100 times
  for (j in seq_len(100)){
    # Sample 200 individuals with replacement
    bootstrap <- slice_sample(samp_df, n = 200, replace = TRUE)
    # Calculate the 0.75 quantile
    quan75 <- quantile(pull(bootstrap, time), 0.75)
    # Store the result
    quans <- c(quans, quan75)
  }
  # Find the confidence interval
  ci <- quantile(quans, c(0.025, 0.975))
  # Check if the population value is in the CI
  has_pop <- between(pop, ci[1], ci[2])
  # Append to the results vector
  results <- c(results, has_pop)
}
# Calculate the percentage
perc <- sum(results) / 100
print (perc)
    [1] 0.96

    The bootstrapped confidence interval for the estimator contains the population value 96% of the time.
