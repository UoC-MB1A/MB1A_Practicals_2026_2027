    We can now align each gene sequence with the protein sequences of the same gene from other retroviruses in a multiple sequence alignment and then build a phylogeny to see the evolutionary relationships between our sequences and their relatives.

    To build these multiple sequence alignments, we first need to build AAStringSet objects for each gene, containing the ORF we identified for that gene along with the sequences of known retrovirus proteins from the same gene and genus, which we identified earlier using BLASTp.

    I will take you through this process with one of my ORFs, Ccan_ERV_1_ORF_4, which is a gag gene from the gamma genus.

    First, I will create an AAStringSet with just this one sequence.

    identified_current <- identified_orf_seqs["Ccan_ERV_1_ORF_4"]

print(identified_current)

    Now I can generate a multiple sequence alignment for these sequences directly in R, using the msa() function. We will use the MSA tool Muscle.

    msa() outputs a different type of variable (called a MsaAAMultipleAlignment), but we can convert it back to an AAStringSet with the as() function.

    combined_current_aligned <- msa(combined_current, method = "Muscle")
combined_current_aligned_ss <- as(combined_current_aligned, "AAStringSet")

    I will save the aligned sequences into a new FASTA file, in my output directory, named gene_Ccan_ERV_j_ORF_i.fasta, replacing gene with the gene I am currently analysing (gag, pol or env), ERV_j with my ERV ID and i with my ORF ID.

    writeXStringSet(combined_current_aligned_ss, "output/gag_Ccan_ERV_1_ORF_4.fasta")

    You can look at this file directly in a text editor, however it’s quite difficult to see details of the alignment in this format. Alternatively, you can upload the sequence to an online alignment viewer, such as Alignment Viewer.

    Note

    Retroviruses, especially endogenous retroviruses, are very divergent, so the sequences might not look to be particularly well aligned - don’t worry, this is expected.

    Build phylogenies

    Core

    ↑ top

    There are various ways we can create phylogenies from our sequences. We will use a distance-based, neighbour-joining approach.

    First, we create a distance matrix for our sequences, then we use the function nj() from the package ape to create a tree.

    A distance matrix contains an estimate of the evolutionary distance between every pair of sequences in our alignment. Smaller distances indicate more similar sequences. The neighbour-joining method uses these distances to construct a tree in which more similar sequences tend to be grouped together.

    I will again demonstrate this process with one of my ORFs, Ccan_ERV_1_ORF_4, which is a gag gene from the gamma genus. These are currently aligned with the related sequences we identified with BLAST and stored in my combined_current_aligned_ss variable.

    First, I will read the relevant FASTA file. We use readAAStringSet() rather than readDNAStringSet() because our sequences are in amino acid format.

    fasta_current <- readAAStringSet(
  "output/gag_Ccan_ERV_1_ORF_4.fasta")

    Next, we make a distance matrix based on our aligned sequences, using the function DistanceMatrix(), with one argument, our new fasta_current variable.

    distance_matrix <- DistanceMatrix(fasta_current)
    ================================================================================

Time difference of 0 secs

    Now, we’re ready to make our neighbour-joining tree. This is very easy in R, just using the function nj().

    tree <- nj(distance_matrix)

    We can save it with the function write.tree(). The standard format for saving phylogenetic trees is called Newick format and has the suffix .nwk.

    write.tree(tree, file = "output/gag_Ccan_ERV_1_ORF_4.nwk")

    Visualise phylogenies

    Core

    ↑ top

    Once the phylogenetic analyses are complete, we can then read our trees into R using the function read.newick().

    For example, for my output/gag_Ccan_ERV_1_ORF_4.nwk Newick file:

    current_newick <- read.newick("output/gag_Ccan_ERV_1_ORF_4.nwk")

    To visualise phylogenies in R, a good option is the ggtree() package, which works similarly to ggplot().

    First, we call the ggtree() function and give our new tree object as an argument.

    ggtree(current_newick)
    ! The tree contained negative edge lengths. If you want to ignore the edges,
you can set `options(ignore.negative.edge=TRUE)`, then re-run ggtree.

    As you can see, this generates a basic tree, but the branch tips are not labelled.

    To label them, we add the function geom_tiplab(). The size argument to geom_tiplab() sets the font size. As our tip labels are quite long, we also change the x axis limits to make some space.

    Note

    Sometimes, the Quarto figure size will be too small to display your tree nicely. You can adjust this by clicking on the “Settings” button at the top of the code chunk and changing the width and height options.

    ggtree(current_newick) +
  geom_tiplab(size = 2) +
  coord_cartesian(xlim = c(0, 20))
    ! The tree contained negative edge lengths. If you want to ignore the edges,
you can set `options(ignore.negative.edge=TRUE)`, then re-run ggtree.

    You should be able to find your ERV gene in the phylogeny. However, it would be helpful to make it clearer, for example by changing the colour.

    Here, we subset the tip labels to label != "Ccan_ERV_1_ORF_4" and label == "Ccan_ERV_1_ORF_4" and assign colours to each set.

    ggtree(current_newick) +
  geom_tiplab(aes(subset = label != "Ccan_ERV_1_ORF_4"),
    color = "black", size = 2
  ) +
  geom_tiplab(aes(subset = label == "Ccan_ERV_1_ORF_4"),
    color = "red", size = 3
  ) +
  coord_cartesian(xlim = c(0, 20))
    ! The tree contained negative edge lengths. If you want to ignore the edges,
you can set `options(ignore.negative.edge=TRUE)`, then re-run ggtree.

    It’s also good practice to add a scale bar to your tree. The scale bar represents evolutionary distance, in substitutions per site.

    Change the x and y co-ordinates to move it around so it’s not displayed on top of your tree.

    ggtree(current_newick) +
  geom_tiplab(aes(subset = label != "Ccan_ERV_1_ORF_4"),
    color = "black", size = 2
  ) +
  geom_tiplab(aes(subset = label == "Ccan_ERV_1_ORF_4"),
    color = "red", size = 3
  ) +
  coord_cartesian(xlim = c(0, 20)) +
  geom_treescale(x = 0, y = 0, fontsize = 3)
    ! The tree contained negative edge lengths. If you want to ignore the edges,
you can set `options(ignore.negative.edge=TRUE)`, then re-run ggtree.

    You can save your tree as a PDF using ggsave(), again you may need to adjust the width and height to fit it nicely on the page, you can do this with the width and height arguments.

    tree_plot <- ggtree(current_newick) +
  geom_tiplab(aes(subset = label != "Ccan_ERV_1_ORF_4"),
    color = "black", size = 2
  ) +
  geom_tiplab(aes(subset = label == "Ccan_ERV_1_ORF_4"),
    color = "red", size = 3
  ) +
  coord_cartesian(xlim = c(0, 20)) +
  geom_treescale(x = 0, y = 0, fontsize = 3)
    ! The tree contained negative edge lengths. If you want to ignore the edges,
you can set `options(ignore.negative.edge=TRUE)`, then re-run ggtree.
    ggsave(
  "output/gag_Ccan_ERV_1_ORF_4.pdf",
  plot=tree_plot,
  width = 10,
  height = 10
)

    NoteSummary

    You have now completed the first ever phylogenetic analysis for your ORFs!

    • Multiple sequence alignments arrange related sequences so that homologous positions are aligned.
    • The msa() function can be used to generate multiple sequence alignments from sets of biological sequences.
    • We can create a distance matrix for our sequences using DistanceMatrix().
    • The nj() function can be used to construct a neighbour-joining phylogenetic tree from a distance matrix.
    • Phylogenetic trees can be saved in Newick format using write.tree().
    • ggtree can be used to visualise and annotate phylogenetic trees.

    Remember to save your work before moving on to Part 5. As we’re now finished with our main analysis, you can push your changes to GitHub.
