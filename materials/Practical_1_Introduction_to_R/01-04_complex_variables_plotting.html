    Packages

    ↑ top

    Core

    R comes with many useful functions, but additional functions are available in packages. Packages are collections of functions and other resources designed for particular purposes.

    Normally, you need to install a package once before you can use it, and load it each time you start a new R session in which you want to use it.

    Let’s install the package fortunes, to demonstrate.

    install.packages("fortunes")
    Installing package into '/home/katy/R/x86_64-pc-linux-gnu-library/4.6'
(as 'lib' is unspecified)

    We can then load the package into R using the function library():

    library(fortunes)

    This package just includes one function, fortune(), which outputs a random quote about R.

    Vectors

    ↑ top

    All of the variables we’ve created so far just have a single element - one number, one section of text, or one TRUE/FALSE.

    However, we can also create variables which contain multiple elements.

    One of the most common ways of storing multiple values in R is a vector.

    Vectors in R are (usually) specified using the function c().

    my_first_vector <- c(1, 5, 9)
print(my_first_vector)
    [1] 1 5 9

    You can have vectors with all numbers, all text, or all logical values, but everything needs to be the same type.

    character_vec <- c("hello", "this", "is", "a", "character", "vector")
print(character_vec)
    [1] "hello"     "this"      "is"        "a"         "character" "vector"   
    logical_vec <- c(TRUE, FALSE, TRUE)
print(logical_vec)
    [1]  TRUE FALSE  TRUE

    If you have existing variables, you can put them into a vector using their variable names.

    x <- 1
y <- 2
z <- 3

xyz_vec <- c(x, y, z)

    Accessing elements of a vector

    Once our values are in a vector, we can access them using an index, which refers to the position of the value within the vector. Indices are indicated within square brackets - [].

    NoteOne-based indexing

    If you’ve previously used a language such as Python, you’ll notice that indexing in R is 1-based - so the first element in a vector is element 1 - rather than 0-based.

    nice_food <- c("cheese", "beans", "potatoes")

print(nice_food[1])
    [1] "cheese"
    print(nice_food[2])
    [1] "beans"
    print(nice_food[3])
    [1] "potatoes"

    Vectorisation

    Extension

    One useful feature of R is vectorisation. Many R operations can be applied to an entire vector at once.

    For example, adding 10 to a vector adds 10 to every element:

    x <- c(1, 2, 3, 4, 5)
print(x + 10)
    [1] 11 12 13 14 15

    Similarly, functions will often operate on every element of a vector:

    print(sqrt(x))
    [1] 1.000000 1.414214 1.732051 2.000000 2.236068

    Data Frames

    ↑ top

    Core

    Our next variable type is a data frame, which is one of the types of data structure you’ll most commonly use. A data frame is basically a table, consisting of rows and columns. Each row is a single record, corresponding to some entity - a cell, a person, a country - and each column is a specific piece of information.

    For example:

    fruit length weight
    apple 22 150
    pear 30 165
    banana 55 170

    In this data frame, there are three columns - fruit, length and weight, and three rows, each containing information about a specific fruit.

    We can build a data frame using the R function tibble() (note that there is also an R function data.frame() which you might see referenced elsewhere, usually modern applications use tibble() as it is more user-friendly).

    I would specify the data frame above as follows:

    my_data_frame <- tibble(
  fruit = c("apple", "pear", "banana"),
  length = c(22, 30, 55),
  weight = c(150, 165, 170)
)


print(my_data_frame)
    # A tibble: 3 × 3
  fruit  length weight
  <chr>   <dbl>  <dbl>
1 apple      22    150
2 pear       30    165
3 banana     55    170

    You can also use existing vectors to put data into the data frame columns.

    fruits <- c("apple", "pear", "banana")
lengths <- c(22, 30, 55)
weights <- c(150, 165, 170)

my_data_frame <- tibble(
  fruit = fruits,
  length = lengths,
  weight = weights
)


print(my_data_frame)
    # A tibble: 3 × 3
  fruit  length weight
  <chr>   <dbl>  <dbl>
1 apple      22    150
2 pear       30    165
3 banana     55    170

    Although we can see our data frame using the print() function, it’s not formatted particularly nicely. Instead, we can use the function gt() to display a nicely formatted version of our data frame in our Quarto document.

    my_data_frame <- tibble(
  fruit = c("apple", "pear", "banana"),
  length = c(22, 30, 55),
  weight = c(150, 165, 170)
)

gt(my_data_frame)

    apple 22 150
    pear 30 165
    banana 55 170

    CSV Format

    ↑ top

    Core

    The data we will use in many of our practicals is stored in comma-separated values (CSV) format, a plain-text file format where each line represents a row and values in columns are separated by commas.

    For example, for this table:

    fruit length weight
    apple 22 150
    pear 30 165
    banana 55 170

    The contents of the CSV file would be:

    fruit,length,weight
apple,22,150
pear,30,165
banana,55,170

    There is a file provided in your data folder for Practical 1 named weather_data.csv. Open this file on your computer in a text editor (for example NotePad, TextEdit) and examine it.

    Downloading data via an API

    Often, when we want to work with data which is regularly updated, we will use an application programming interface (API) to directly access data programmatically. UKHSA provides an API for accessing the data underlying its dashboard.

    The UKHSA API is organised hierarchically. Navigating its hierarchical structure takes a little getting used to.

    To find a dataset, we need to work through several levels:

    theme → sub_theme → topic → geography_type → geography → metric

    Start by opening this URL in your browser:

    https://api.ukhsa-dashboard.data.gov.uk/themes/

    Here, you need to navigate through the theme, then sub-theme, then topic, geography_type, geography. This should lead you to a list of metrics, each with a name and a link. The names of these metrics are not exactly intuitive, but you can find out what they mean by searching for them by name here.

    For example, I have chosen Clostridioides. difficile monthly cases by onset type, for which the link is:

    https://api.ukhsa-dashboard.data.gov.uk/themes/infectious_disease/sub_themes/gastrointestinal/topics/C-difficile/geography_types/Nation/geographies/England/metrics/c-difficile_cases_countsByOnsetType

    Now we can access the data via the API.

    We need to import a package, httr2.

    library("httr2")

    We can also assign our URL to a variable.

    url <- "https://api.ukhsa-dashboard.data.gov.uk/themes/infectious_disease/sub_themes/gastrointestinal/topics/C-difficile/geography_types/Nation/geographies/England/metrics/c-difficile_cases_countsByOnsetType"

    We need to append this to our URL - ?page_size=365. You have probably seen similar additions to URLs before, which tell a website more specifically what you want it to show you. These are called query parameters. Here, page_size=365 tells the UKHSA API to return up to 365 records.

    Note

    The API allows a maximum of 365 records per page. Some datasets contain more than 365 records, so this may not retrieve the complete dataset. For this exercise, it does not matter.

    You can concatenate strings in R using the function paste0, as follows:

    url <- paste0(url, "?page_size=365")
print(url)
    [1] "https://api.ukhsa-dashboard.data.gov.uk/themes/infectious_disease/sub_themes/gastrointestinal/topics/C-difficile/geography_types/Nation/geographies/England/metrics/c-difficile_cases_countsByOnsetType?page_size=365"

    Now we are ready to import our data. First, we structure a request for the data from the URL, using the function request().

    api_request <- request(url)

    Next, we use the function req_perform() to perform the request we’ve built.

    response <- req_perform(api_request)

    The returned data is encoded in JSON format, a common and useful data format used for storing and transferring data. The function resp_body_json() reads this JSON data into an R object.

    json_response <- resp_body_json(response)

    All of our data is now in this object. We can describe the object using the R function str(), which displays the structure of an R object. The argument max.level = 1 tells R to only show the top level of information (otherwise it will show us something for every data frame row).

    str(json_response, max.level = 1)
    List of 4
 $ count   : int 126
 $ next    : NULL
 $ previous: NULL
 $ results :List of 126

    The part we are interested in is contained in $results - this is a list of observations, which will become the rows in our data frame. We haven’t encountered R lists yet. Lists are a flexible way of storing multiple objects in R, but they are trickier than vectors, so we won’t cover them until Practical 6.

    We don’t want our results to be in a list, we want a data frame. We can convert a list to a data frame using the function bind_rows().

    results_df <- bind_rows(json_response$results)

    This may seem like a lot of work to do something you could do manually in two minutes! The advantage of an API is that the process can now be automated. The same code can retrieve newly updated data without somebody having to visit the website and download a new file each time. Programmatic data retrieval can also make an analysis more reproducible and reduce opportunities for manual error. For example, during COVID many websites pulled data from the UKHSA website to display or otherwise use specific aspects of the data.

    Initiating a plot

    We will now learn to draw some basic graphs in R. We will learn much more about this over future weeks.

    We start a new, empty plot using the function ggplot. The input for this function is our data frame variable, which contains the data we are going to plot.

    Adding axes

    We use another function, aes(), as an argument to the ggplot() function, telling R how various attributes of the data map to the “aesthetics” of the plot.

    For example, here we choose which data we will represent with the x and y axes.

    ggplot(weather, aes(
  x = observation_time,
  y = temperature_c
))

    Adding data

    Now we can add some data to our plot. In ggplot2, we build plots by adding layers using the + symbol.

    Here, we add a line representing the data using the geom_line() function.

    ggplot(weather, aes(
  x = observation_time,
  y = temperature_c
)) +
  geom_line()

    Adding extra features

    We can add some additional features here to make the plot look nicer. For example, here I will change the colour of the line to red (with colour = "red" as an argument to geom_line()), add x (xlab()) and y (ylab()) axis labels and add a title (ggtitle()).

    ggplot(weather, aes(
  x = observation_time,
  y = temperature_c
)) +
  geom_line(colour = "red") +
  xlab("Date") +
  ylab("Temp (C)") +
  ggtitle("Temperature by Date")

    NoteSummary

    Concepts

    • Packages contain additional functions and other resources. Packages need to be installed once and loaded using the library() function in each new R session in which they are used.
    • A vector (c()) stores multiple values of the same type.
    • Indexing with square brackets ([]) allows us to access individual elements of a vector by position in the vector.
    • A data frame (tibble()) stores tabular data in rows and columns.
    • CSV (comma-separated values) is a plain-text format commonly used to store tabular data.
    • ggplot2 builds plots in layers. Variables are mapped to features of the plot using aesthetics.
    • Vectorisation allows an operation or function to be applied to all elements of a vector at once. (Extension)
    • An API allows data to be accessed programmatically. (Bonus)
